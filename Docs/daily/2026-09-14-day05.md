波形未标注探头所接 GPIO，也没有同时保存低任务 20 ms 窗口与高任务波形，因此不将它单独认定为双通道抢占证明。两次快照的采集时间是人工记录，任务计数与 Tick 比值比墙钟秒数更适合此处判断。

正常日志中 `assert_file=0x0` 且 failure=NONE；其下的 `*assert_file=112 'p'` 是展开空指针后的无效观察，不作为 Assert 文件内容。后续只在指针非空且 failure=ASSERT 时读取文件名。

## 收尾修正

发现 KEY1 的生成代码仍为 `HAL_NVIC_SetPriority(EXTI9_5_IRQn, 4, 0)`，而 `.ioc` 已是 5；`main.c` 中还遗留对低任务调用 `vTaskNotifyGiveFromISR()` 的故障测试回调。按键会再次触发 Assert，且对象创建之前触发存在空句柄风险。

收尾将优先级恢复为 5、移除该故障回调和外部句柄声明、将低任务句柄恢复为模块私有；同时移除 main 中无用的 `Task.h`/FreeRTOS 引用，以及无 RTOS 类型的 demo 头文件对 FreeRTOS.h 的反向依赖。两个任务周期、Hook 和诊断统计保持原实现；Malloc/Stack 故障开关均为 0。Day 6 按键通知将使用自己的任务与正确的初始化顺序。

以上修正通过重新编译与静态审计，**收尾版尚未由助手重新烧录验证**。进入 Day 6 时先烧录 Debug 版，复查两个计数持续增长、failure=NONE，并按 KEY1 确认不再进入 Assert，保存一份带固件指纹的新日志。

从仓库根目录载入环境，然后在 `project/my_project` 执行：

## 仍需保留的事项

- Bootloader 跳转时关闭全局中断，应用目前在 MX 初始化全部完成后才恢复。初始化期间 HAL Tick 不增长，LSE 失败时超时可能无法退出；后续启动交接整理时处理。当前日志证明正常条件可启动，没有验证故障超时路径。
- ADC 电池采样、SPI DMA 和未执行的 EXTI/启动重复测试仍待补齐；不能因 RTOS 正常直接认定整板外设全部通过。
- UART IRQ 中手动预清 IDLE 的旧代码目前没有启动 RX；Day 6 使用 HAL ReceiveToIdle 前必须移除，否则 HAL 收不到 IDLE 事件。
- 仅 ST-Link 供电，充电、电源自锁和低功耗继续延期。
- 本机 `git submodule status` 的 shell helper 缺少 basename/sed；本次用子模块直接 git 命令、父仓库 gitlink 和源码版本三者交叉核验，未改动全局 Git 安装。

## 学习记录

头文件包含问题：使用 FreeRTOS API 时先包含 `FreeRTOS.h`，再包含小写 `task.h`。大小写应与官方文件一致，以便在 Linux 等区分大小写的环境中构建。

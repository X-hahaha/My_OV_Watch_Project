## Git 检查点

先在 VSCode Source Control 或终端审查变更：

```powershell
git status --short
git diff --check
git diff
```

三条命令的范围不同：`git status --short` 列出状态，`git diff --check` 检查已跟踪但未暂存修改中的空白错误，`git diff` 显示这些修改的正文。当前 README、Docs、Hardware、tools 等大多是未跟踪文件，所以只运行 `git diff` 看不到它们；VSCode Source Control 中它们会显示 `U`，点击文件即可查看正文。

关闭正在打开 `硬件外设.xlsx` 的 Excel 窗口后，临时文件 `~$硬件外设.xlsx` 应自动消失；`.gitignore` 也已增加 `~$*` 保护。确认内容后可精确暂存本轮文件：

```powershell
git add .gitattributes .gitignore .vscode Docs Hardware README.md tools
git add -u -- .gitignore.txtfile
git diff --cached --stat
git diff --cached --check
git diff --cached
```

`git diff --cached` 展示的就是下一次提交将包含的精确快照。`Docs/evidence/day01/terminal-toolchain-check-001.log` 属于原始证据，受 `*.log` 和 `Docs/evidence/*` 规则忽略，不会被上述命令提交；验证结论已经写进受 Git 管理的文档。本轮按上述范围审查并使用 `chore(repo): prepare day 1 toolchain and baseline records` 创建普通提交。只有实测证据补齐且 Gate 通过，才创建计划中的 `v0.1.0-baseline`。

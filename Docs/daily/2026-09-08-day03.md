## 当前结论

Day 3 的 PC 端工作已经通过复核。Debug 和 Release 均可从空 CMake 缓存完成配置与 38 步编译链接，自动生成 ELF、HEX、BIN 和 MAP；应用向量表、初始 MSP、Reset Handler、Cortex-M4F ABI 与启动早期 VTOR 均通过静态检查。

## 完成内容

- 增加 Debug/Release CMake Preset，构建目录分别为 `build/Debug` 和 `build/Release`。
- GNU Arm 工具链从 PATH 查找编译器、objcopy 和 size，项目环境由 `tools/enter-env.ps1` 提供 CMake、Ninja 和 OpenOCD。
- 增加应用链接脚本 `linker/STM32F411CEU6_APP.ld`：Flash 起始地址 `0x0800C000`、长度 `0x74000`，SRAM 起始地址 `0x20000000`、长度 `0x20000`。
- 固定 Cortex-M4F、硬件浮点和 Thumb 编译参数；Debug 使用 `-Og -g3`，Release 使用 `-Os`。
- 链接时生成 MAP、启用 `--gc-sections` 并输出内存占用；链接后自动生成 HEX 和 BIN。
- `SystemInit()` 通过 `USER_VECT_TAB_ADDRESS` 和 `VECT_TAB_OFFSET=0x0000C000U` 在启动早期设置 VTOR；`main()` 中保留带 `DSB/ISB` 的防御性设置。
- 增加 VS Code Task、Cortex-Debug/OpenOCD、SVD 和 CMake Tools 配置。Task 会自行加载项目工具环境，CMake Tools 使用仓库 `.tools` 中的 CMake 和 Ninja。

## 配置问题及处理

- 初版工具链在成功执行 `find_program()` 后又用未定义的 `TOOLCHAIN_PATH` 覆盖编译器路径，导致空缓存配置失败；现已保留 PATH 探测结果。
- 初版使用了不存在的 `VECT_TAB_ADDR` 宏，导致 `SystemInit()` 写入 `0x08000000`；已改为 STM32 系统文件实际读取的 `VECT_TAB_OFFSET`。
- 初版 `launch.json` 的预启动任务名、OpenOCD 路径和脚本搜索目录不完整；现已静态核对。
- CMake Tools 不继承单个终端执行 `enter-env.ps1` 后的 PATH；工作区设置现已直接指定项目内的 `cmake.exe`，并为扩展加入 Ninja 路径。
- 切换到 `CMAKE_C_FLAGS_INIT` 后，已有构建缓存不会自动重置基础架构参数。本次已使用 `cmake --fresh --preset Debug/Release` 重建缓存；修改工具链基础参数后应再次执行 `--fresh`。

Debug 编译命令中的 `DEBUG` 宏目前被等价定义两次，不影响生成结果；后续整理构建文件时可删除顶层 `CMAKE_C_FLAGS_DEBUG` 中的 `-DDEBUG`，保留 CubeMX 生成的条件定义。
